# Gas-golf tricks catalogue

Every optimization in the golfed code is listed here with four things: where it lives, its measured
effect, the property it could break, and the evidence that guards that property. The numbers in the two
tables below are generated by `scripts/gen-tables.mjs` from `snapshots/GasBench.json`; CI fails if they
drift (`node scripts/gen-tables.mjs --check`).

## Measured micro-benchmarks

Each trick is isolated in an A/B probe (`test/gas/TrickProbes.sol`, driven by `GasBench.test_Tricks`;
the probe comments use the trick numbers below). "gas" rows are a GAS-to-GAS window inside one probe
contract that holds both variants, so the constant measurement overhead is identical and cancels in the
saving; everything a variant needs (immutables, arguments) is read inside its window. Two kinds of row are
metered by a calling contract instead: `selector_errors_call`, because a whole failing transaction is
dominated by the EIP-7623 calldata floor (both variants cost exactly the floor), and the `dispatch_` rows,
because dispatch happens before any code a GAS window could wrap (two fallback-only probes with the
token's twelve selectors). "bytes" rows compare runtime code size. T12 and T14 are measured by the kernel
tables (the README's and the one below); every other trick has a row here.

A negative saving is a cost. Several results are worth calling out. Returning from scratch space saves gas
but adds bytecode (T4). `mul(signer, eq(signer, owner))` saves a single gas unit (T6), and the xor-or
cache check two (T7). Frequency ordering (T11) is a trade, not a free win: `transfer` dispatches cheaper,
the rarely used `DOMAIN_SEPARATOR` at the end of the chain dearer. The small ones stay in the code
because they are on the hot path of every call, and the table says how small they are.

## CLZ versus the pre-Osaka fallback

Two comparisons, execution gas of one library call. "Legacy" runs the same algorithms as the golfed
kernel with an emulated count (Solady's fused `clz`), so that saving is the opcode alone. "Best
pre-Osaka" is the cheapest code that runs without CLZ among Legacy, OpenZeppelin 5.7 and Solady 0.1.26:
what upgrading to Osaka buys over the best available alternative. For `sqrt` that is Solady's own
algorithm, which beats our seed-and-six-steps `sqrt` once CLZ has to be emulated.

## Why six Newton steps are enough for `sqrt`

With `e = floor(log2 x)` and `s = e >> 1`, the seed `(x / 2**s + 2**s) / 2` is the tangent of `sqrt`
at `4**s`, which over-estimates `sqrt(x)` by at most a factor 1.25 (worst case: odd `e`, `x` just below
`2**(e+1)`). Newton's relative error obeys `e' = e**2 / (2 (1 + e))`, so from `0.25` it goes
`0.025, 3.0e-4, 4.7e-8, 1.1e-15, 5.8e-31, 1.7e-61`. After six steps the exact-arithmetic error is far
below one unit for any result below `2**128`; the final `z -= (x / z < z)` removes the integer +1
overshoot. Five steps are **not** enough: a simulation over every bit length found 2,092 failures with
five steps and none with six, and the tests check every bit length, both ends of every bit length, every
perfect square `k**2` and its neighbours for `k = 2**j - 1, 2**j, 2**j + 1`, and all inputs below 2\*\*16.

## Memory safety

Every inline-assembly block in `src/` is annotated `assembly ("memory-safe")` and carries a comment
stating which memory it touches. They fall into three groups, all within the rules the Solidity
documentation sets for the annotation:

- **No memory access** (math kernel, cache checks).
- **Scratch space only** (`0x00`-`0x3f`): slot hashing, event data, 4-byte reverts, 32-byte returns.
- **Memory at the free memory pointer, pointer not moved** (`permit` hashing, `name`/`symbol`, the domain
  separator): the block either ends the call (`return`) or leaves nothing that compiler-generated code
  reads back.

No block writes the free memory pointer (`0x40`) or the zero slot (`0x60`), unlike some well-known
libraries that write and then restore them. The Yul object owns all of memory, so the rules do not apply
there.
